# MediX 多智能体医疗助手 — 项目详细分析

## 一、项目概述

**项目名称**：MediX Agent Swarm（多智能体医疗助手）

**核心定位**：基于 Skills-Agent 两层架构的多智能体协作医疗咨询系统

**技术理念**：
- Skills 直达 LLM（函数直接转换为 OpenAI function calling 格式）
- Agent Swarm 群体智能（去中心化协作、并行执行）
- Harness Engineering（约束驱动 + 熵管理 + 自动修复）

**Python 版本**：>= 3.10（推荐 3.12）

## 三、核心模块详细分析

### 3.1 核心引擎层（`core/`）

| 文件 | 职责 | 关键设计 |
|------|------|----------|
| `agent_loop.py` | Agent 循环引擎（Think-Act-Observe） | LLM 驱动 Skill 调用循环，最大迭代保护，集成约束验证 |
| `llm_client.py` | LLM 统一客户端 | 基于 AsyncOpenAI，支持 function calling，指数退避重试 |
| `skill_registry.py` | Skill 注册表 | 函数 → OpenAI format 直接转换，支持同步/异步执行 |
| `skill_loader.py` | Skill 动态加载器 | 扫描 `.claude/skills/` 目录，自动发现并加载 Skill 函数 |
| `state_manager.py` | 状态管理器 | 管理 Agent 执行状态（PENDING → IN_PROGRESS → COMPLETED/FAILED） |

**Agent Loop 核心流程**：
```
初始化消息（system + 历史对话 + 用户输入）
    │
    ▼
┌─── 循环开始 ───────────────────────────────┐
│  调用 LLM（带 tools 参数）                  │
│      │                                     │
│      ├─ 返回 tool_calls → 执行 Skill       │
│      │     → 约束验证 → 结果回注 messages   │
│      │     → 继续循环                       │
│      │                                     │
│      └─ 返回文本 → 输出验证 → 自动修复     │
│            → 记录短期记忆 → 结束循环        │
└────────────────────────────────────────────┘
```

**关键限制机制**：
- `max_iterations = 10`：防止无限循环
- `max_tool_calls = 2`：硬性限制 Skill 调用次数
- 超时后强制生成最终答案

---

### 3.2 Agent 层（`agents/`）

| Agent | 职责 | 能力标签 |
|-------|------|----------|
| `ConsultationAgent` | 健康咨询、生活方式指导 | general_health_advice, risk_assessment, symptom_triage |
| `DiagnosticAgent` | 症状分析、鉴别诊断 | symptom_analysis, differential_diagnosis, clinical_reasoning |
| `ResearchAgent` | 文献检索、证据综合 | literature_search, evidence_synthesis, guideline_lookup |

**设计模式**：
- **模板方法模式**：`BaseAgent` 定义骨架，子类实现 `get_system_prompt()` 和 `register_tools()`
- **Mixin 模式**：`SkillRegistryMixin` 提供统一的 Skill 自动发现和注册逻辑，三个 Agent 共享
- **策略模式**：每个 Agent 通过不同的 system prompt 定义不同的行为策略

**Skill 注册流程**：
```
Agent.__init__()
  → register_tools()
    → SkillRegistryMixin.register_all_skills()
      → skill_loader.discover_skills()  # 扫描 .claude/skills/
        → 解析 SKILL.md（YAML frontmatter）
        → 动态 import 脚本文件
        → 推断函数参数（inspect.signature）
      → SkillRegistry.register()
```

### 3.3 Swarm 协作层（`swarm/`）

| 组件 | 职责 | 设计灵感 |
|------|------|----------|
| `SwarmCoordinator` | 智能路由入口 | 交通信号灯（路由而非控制） |
| `LeadAgent` | 任务分解 + 结果汇总 | 团队 Leader（分配+总结） |
| `SharedContext` | 共享环境（黑板系统） | 蚁群信息素 |
| `Events` | 事件驱动通信 | 发布-订阅模式 |

**Swarm 协作流程**：
```
用户问题
    │
    ▼
SwarmCoordinator.process()
    │
    ├─ 检索短期记忆（会话历史）
    ├─ 检索长期记忆（Mem0 相似案例）
    │
    ▼
LeadAgent.assess_and_decompose()
    │  （LLM 判断复杂度，输出 JSON 子任务列表）
    │
    ├─ 1个子任务 → 单 Agent 模式
    │       → agent.process() → 返回结果
    │
    └─ ≥2个子任务 → Swarm 模式
            │
            ▼
        SharedContext 创建
            │
            ▼
        LeadAgent.create_subtasks() → 发布到 SharedContext
            │
            ▼
        Worker 并行执行（asyncio.gather）
        ┌──────────┬──────────┬──────────┐
        │ConsultAgent│DiagAgent│ResearchAgent│
        └──────────┴──────────┴──────────┘
            │  （每个 Worker 内部运行 Agent Loop）
            ▼
        LeadAgent.synthesize_results()（LLM 汇总）
            │
            ▼
        SessionSummary 生成 + Mem0 长期记忆保存
```

**关键设计决策**：
- LeadAgent **不是编排器**：只分解任务和汇总结果，不控制执行顺序
- Worker 通过 `assigned_agent` 字段被分配任务（中心化分配，去中心化执行）
- 超时机制：90 秒全局超时，超时后仍尝试汇总已完成的部分结果

### 3.4 记忆系统（`memory/`）

#### 短期记忆（`short_term.py`）
- **存储**：内存（默认）或 Redis（可选）
- **容量**：最近 10 条消息
- **生命周期**：会话级（Redis 模式 1 小时过期）
- **设计模式**：单例模式
- **熵管理集成**：自动去重（MD5 哈希）+ 压缩（保留最近消息，摘要化早期消息）

#### 长期记忆（`long_term.py`）
- **后端**：Mem0 云服务（向量相似度搜索）
- **内容**：会话总结（问题 + 回答摘要）
- **检索**：语义相似度匹配历史案例
- **降级策略**：Mem0 不可用时系统继续工作（仅使用短期记忆）

#### 熵管理器（`entropy_manager.py`）
- **去重**：基于 MD5 内容哈希
- **压缩**：超过阈值后将早期 user+assistant 对压缩为摘要
- **估算**：计算重复率、平均长度、熵等级（low/medium/high）
- **自动清理**：`auto_clean()` 一键执行去重+压缩

#### 会话总结（`session_summary.py`）
- 每次 Swarm 协作后自动生成
- 记录：参与 Agent、子任务完成情况、关键发现、性能指标
- 存储为 Markdown 文件（`memory/swarm/session_summaries/`）

### 3.5 知识库（`knowledge/`）

| 组件 | 技术 | 说明 |
|------|------|------|
| 向量数据库 | Milvus Lite（本地文件） | 无需服务器，`milvus_lite.db` |
| Embedding | BAAI/bge-small-zh-v1.5 | 中文模型，512 维，COSINE 相似度 |
| 文档分块 | 1024 字符/块，100 字符重叠 | 滑动窗口分块策略 |

**知识类型**：
- `lifestyle`：生活方式建议（高血压、糖尿病、感冒等）
- `disease_classification`：ICD-10 疾病编码
- `clinical_guideline`：临床诊疗指南

**检索能力**：
- 语义模糊匹配（"血压高" → "高血压"）
- 按类型过滤（`filter_type` 参数）
- 相似度评分

---

### 3.6 约束系统（`constraints/` + `validation/`）

**Harness Engineering 三原则**：

| 原则 | 实现 | 文件 |
|------|------|------|
| 约束驱动 | YAML 定义 Agent 能力边界 | `agent_constraints.yaml`, `swarm_constraints.yaml` |
| 运行时验证 | 工具调用前验证 + 输出后验证 | `validator.py` |
| 自动修复 | 缺少免责声明/高危警告 → 自动补充 | `auto_fixer.py` |

**约束验证点**：
1. **工具调用前**：`validate_tool_call()` — 检查是否在允许列表中（警告级别，不阻止）
2. **输出生成后**：`validate_output()` — 检查免责声明、高危就医建议、长度限制、越界行为
3. **任务分解时**：`validate_task_decomposition()` — 检查子任务数量是否合理

**自动修复能力**：
- 缺少免责声明 → 自动追加
- 高危症状未建议就医 → 自动添加警告
- 输出过长 → 截断
- 明确诊断语句 → 替换为委婉表达

### 3.7 深度研究模块（`research/`）

| 组件 | 功能 |
|------|------|
| `WebSearchTool` | DuckDuckGo 搜索（多后端：bing/duckduckgo/auto），医学域名白名单 |
| `MedicalKnowledgeBase` | Milvus 语义检索（与 Skills 共享单例） |
| `EvidenceSynthesizer` | LLM 驱动的证据综合，生成结构化报告 |
| `DeepResearchWorkflow` | 多步骤编排：查询规划 → 并行搜索 → 证据综合 → 质量验证 |

**研究报告输出结构**：
- 关键发现（3-5 条）
- 证据等级（A/B/C）
- 置信度（0-1）
- 信息冲突
- 综合总结
- 建议

## 七、设计模式识别

| 模式 | 应用位置 | 说明 |
|------|----------|------|
| **模板方法** | `BaseAgent` | 定义 Agent 骨架，子类实现具体 prompt 和工具注册 |
| **Mixin** | `SkillRegistryMixin` | 三个 Agent 共享 Skill 注册逻辑 |
| **单例** | `ShortTermMemory`, `MedicalKnowledgeBase` | 避免重复初始化和资源浪费 |
| **策略** | 不同 Agent 的 system prompt | 同一框架不同行为 |
| **观察者/发布-订阅** | `SharedContext` + `Events` | Agent 间事件驱动通信 |
| **黑板系统** | `SharedContext` | 去中心化共享数据空间 |
| **工厂方法** | `skill_loader.discover_skills()` | 动态发现和创建 Skill |
| **装饰器/非侵入集成** | 约束系统注入 AgentLoop | try-import 优雅降级 |
| **状态机** | `StateManager` + `TaskStatus` | 管理任务生命周期 |

## 八、项目优势

1. **架构清晰**：Skills-Agent 两层分离，Skill 自包含，Agent 只负责决策
2. **自动发现**：Skill 通过目录扫描自动注册，添加新 Skill 无需修改 Agent 代码
3. **优雅降级**：Mem0 不可用、约束模块不存在时系统仍能正常工作
4. **安全约束**：YAML 定义能力边界 + 运行时验证 + 自动修复，医疗场景安全性好
5. **熵管理**：自动去重和压缩，防止记忆系统无限膨胀
6. **并行执行**：Swarm 模式下多 Agent 通过 asyncio 并行工作
7. **多轮对话**：短期记忆注入 Agent Loop，支持上下文追问
8. **统一知识库**：Milvus 语义检索，支持模糊查询

## 十三、总结

MediX Agent Swarm 是一个**设计完整、架构清晰**的多智能体医疗助手系统。它的核心亮点在于：

1. **Skills 直达架构**：消除了传统 Tool 抽象层的冗余，Skill 函数直接映射为 LLM 可调用的 function
2. **真正的 Swarm 协作**：不是简单的 pipeline，而是基于共享环境的去中心化协作
3. **Harness Engineering**：约束、验证、修复三位一体，保证医疗场景的安全性和可靠性
4. **记忆系统闭环**：短期（会话级）→ 长期（跨会话）→ 熵管理（自动清理），形成完整生命周期

项目适合作为**多智能体系统学习案例**和**医疗 AI 助手原型**，如需生产化部署，建议重点补充 API 层、测试覆盖和监控体系。
